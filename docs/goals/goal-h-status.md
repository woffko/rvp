## Found and fixed

- **The album stopped at the end of a file.** A resync seek (a normalizer
  or equalizer change, and at that time a speed change) that reached mpv
  after the end but before RVP saw it left mpv's `eof-reached` false:
  mpv's log showed the seek restarting playback at the last frame with the
  audio "draining", and RVP never saw the property turn true again, so it
  never moved on. The Windows VM's self-test hit it (Shift+N right at the
  end of a 3 s clip), and once more after the tempo filter came (a chain
  change at the end, without a seek). Changes of RVP's audio filters, and
  their resync seeks, now wait in the last half second of a file and at
  its end: they apply when the next file starts or playback leaves the
  end (`App::defer_chain_change`), and the end counts again once playback
  leaves it. `tests/album_end.rs` reproduces the stop without the fix
  (three of three fail) and checks that the waiting change arrives with
  the next file.
- **The next file started paused** on the Windows VM, although RVP had
  unpaused just before `loadfile` and, by mpv's log, nothing else set the
  pause. (Deduced, not measured: the pause keep-open sets at the end of
  the previous file carried over.) An entry RVP starts to play is now
  unpaused again once it has loaded.
- **Rotation did nothing:** mpv takes `video-rotate` as text, not as a
  double (found by `tests/video.rs`).
- `af-command` with the default target `all` fails (`-12`); it is aimed at
  the equalizer's instance name.
- `deinterlace=auto` needs mpv 0.38; with an older libmpv (the WSL and CI
  headless tests) RVP falls back to off.
- The self-test's resize check timed out once on the Ubuntu VM: 300 ms
  after a resize the window takes the video's shape (M3), which moves its
  size by a few pixels. The check now accepts that.
- `resume.rs::playlists_survive_killed_processes` failed under the load of
  the full test run (goal G saw it once); the window of edits it accepts
  grew from one second to three.

## Differences from PotPlayer

- SVP on Windows serves only the RVP window holding `mpvpipe` (SVP's
  settings name one pipe); a second RVP window tells why SVP did not
  attach.
- Shaders are mpv's GLSL user shaders, in one list; PotPlayer's HLSL pixel
  shaders do not run, and there is no pre- and post-resize split (mpv's
  shaders choose their stage). Display colour management and HDR are
  mpv's.
- Video effects: deblock, denoise 3D, soften, sharpen, the flips and
  deband. PotPlayer's other effects (rotation as an effect, auto levels,
  and the rest listed in `docs/coverage/menus.md`) are not in RVP;
  rotating by the aspect ratio neither.
- The equalizer's presets are RVP's own curves with PotPlayer's names;
  the control panel's volume slider sets RVP's volume, not the system's
  (PotPlayer's "master volume").
- Control panel: no subtitle font choice (PotPlayer's font dialog), and
  subtitles cannot move sideways in mpv. RVP opens the panel at the bottom
  right of the video the first time in a session and does not remember
  its place between sessions.
- One script slot runs at a time. mvtools, which PotPlayer's
  interpolation script needs, ships with neither SVP nor Ubuntu: the user
  adds it as a plugin (the kit builds it on Linux).
